# Jetpack Room

Room is the persistence layer for Split Happens

Version in use: **3.0.3**

## Room 3 vs. the 2.x tutorials

Most tutorials online describe Room 2.x. The differences that matter for us:

- New package and artifacts: `androidx.room3.*`, `androidx.room3:room3-runtime`, `androidx.room3:room3-compiler`.
- KSP is required. Room 3 only generates Kotlin; KAPT and Java annotation processing are gone.
- A `SQLiteDriver` is required to build a database (`setDriver(...)`).
- DAO functions must be `suspend`, or return a reactive type such as `Flow`.
- `@TypeConverter` is renamed `@ColumnTypeConverter`. We currently need no converters.
- `SupportSQLite` APIs are gone; for example `runInTransaction { }` becomes `withWriteTransaction { }`.
- No `Executor` configuration; a `CoroutineContext` is set on the builder instead.

## Conventions

- **Chips:** every chip amount (bankroll, stakes, bets, payouts) is a `Long`.
- **Timestamps:** milliseconds as `Long`, so no converter is needed.
- **Enums:** stored by name as `TEXT`. Renaming a constant is a data migration. The `Suit` and `Rank` ordinals feed card IDs, so never reorder those two.
- **IDs:** only `Users.userId` is a UUID string, because it is the key matched on import. Every other table uses a local auto-generated `Long` key that is reassigned on import.
- **Validation at write time only:** hands and games are built through factories (`HandEntity.player()`, `HandEntity.dealer()`, `GameEntity.create()`). The constructors stay public only because Room needs them. Nothing is validated when rows are read back, so history survives future rule changes.

## Schema

Cascades run User → Session → Game → Hand → HandCards.

### Users

| Column | Type | Notes |
|---|---|---|
| userId | TEXT, PK | UUID string |
| displayName | TEXT | |
| chipsOwned | INTEGER | Current bankroll |
| createdAt | INTEGER | millis |

### ProfilePictures (1:1 with Users)

| Column | Type | Notes |
|---|---|---|
| userId | TEXT, PK and FK to Users | Cascade delete |
| image | BLOB | Downscale (about 256px JPEG) before saving, so rows stay small and the picture is portable in the JSON export |

Kept out of Users so listing profiles never loads image bytes.

### Sessions

| Column | Type | Notes |
|---|---|---|
| sessionId | INTEGER, PK, auto | |
| userId | TEXT, FK to Users | Cascade delete, indexed |
| stakes | INTEGER | Fixed for the session |
| status | TEXT | `SessionStatus`: ONGOING, COMPLETED |
| startedAt | INTEGER | Epoch millis |
| endedAt | INTEGER, nullable | Epoch millis |

### Games

| Column | Type | Notes |
|---|---|---|
| gameId | INTEGER, PK, auto | |
| sessionId | INTEGER, FK to Sessions | Cascade delete |
| gameNum | INTEGER | Unique together with sessionId |
| dealerTotal | INTEGER | Write-once snapshot so history can show it without joining Hands. Busted totals are stored as-is (e.g. 26). |
| insuranceBet | INTEGER | 0 if none. Per round, so it lives here, not on a possibly split hand. |
| insurancePayout | INTEGER | Chips returned: 3x the bet if the dealer had blackjack, otherwise 0 |

### Hands

| Column | Type | Notes |
|---|---|---|
| handId | INTEGER, PK, auto | |
| gameId | INTEGER, FK to Games | Cascade delete, indexed |
| parentHandId | INTEGER, nullable, FK to Hands | Set on a hand created by a split. Cascade delete, indexed. |
| owner | TEXT | `HandOwner`: PLAYER, DEALER |
| betAmount | INTEGER | Final wager, already doubled if the player doubled down. 0 for dealer hands. |
| isDoubled | INTEGER (boolean) | True if the player doubled down. Always false for dealer hands. |
| handStatus | TEXT | `HandStatus`: STOOD, BUSTED, BLACKJACK, SURRENDERED |
| result | TEXT, nullable | `HandResult`. Null for dealer hands. |
| payout | INTEGER | Chips returned when the round settled. 0 for dealer hands. |

Split hands are modeled with `parentHandId`. A hand was split if another hand points at it, so `SPLIT` is deliberately not a status. Because the reference points at a row in the same table, parents must be inserted before their children.

`handStatus` describes how play on the hand ended. `result` is the settlement against the dealer and exists only for player hands. Dealer hands use STOOD, BUSTED or BLACKJACK.

### HandCards

| Column | Type | Notes |
|---|---|---|
| handId | INTEGER, part of PK, FK to Hands | Cascade delete |
| dealtOrder | INTEGER, part of PK | Position in the hand |
| cardId | INTEGER, FK to Cards | Indexed |
| isHoleCard | INTEGER (boolean) | The dealer's face-down card until revealed |

The key is `(handId, dealtOrder)`, not `(handId, cardId)`. With a multi-deck shoe the same card can appear twice in one hand.

### Cards

| Column | Type | Notes |
|---|---|---|
| cardId | INTEGER, PK | Deterministic: `suit.ordinal * 13 + rank.ordinal` |
| suit | TEXT | `Suit` |
| rank | TEXT | `Rank`; unique together with suit |

Static reference data: the same 52 rows are shared by every hand. `cardId` is deterministic so it means the same thing on every device and in every export.

### GameHistory (read-only view)

One row per game, derived on demand from Games, Sessions and Hands: `gameId`, `userId`, `sessionId`, `sessionStartedAt`, `gameNum`, `dealerTotal`, `playerHands`, `netChips`. Nothing is stored, so nothing can drift out of sync with the raw history.

## Payouts

A hand's payout is `betAmount × multiplier`, rounded down. The multiplier is the **total chips returned per chip wagered**, so 1 is the stake back and 2 is the stake plus an equal win. Net profit is `payout - betAmount`.

| `HandResult` | Multiplier | Meaning |
|---|---|---|
| LOSS | 0 | |
| SURRENDER | 0.5 | Half the wager comes back |
| PUSH | 1 | Stake returned |
| WIN | 2 | Any normal win |
| BLACKJACK | 3 | Ace + a ten-value card |
| QUEEN_JACK | 10 | Queen + ace |
| NATURAL_BLACKJACK | 50 | Jack + ace |
| TRIPLE_SEVEN | 100 | 21 with three 7s |
| SIX_CARD | 120 | Six cards without busting |
| SEVEN_CARD | 250 | Seven cards without busting |

The multiplier lives on the enum, so re-balancing it is a one-line edit. `payout` is stored on each hand as a fact, so re-balancing never rewrites history. Which result applies to a hand is decided by the game logic; the database only records it.

### Rules the factories enforce

- A busted hand always has result LOSS.
- Status SURRENDERED and result SURRENDER go together.
- A doubled hand takes one card and ends, so it can only be STOOD or BUSTED.
- The dealer cannot surrender.
- `payout` is derived from `result`, and `insurancePayout` from whether the dealer had blackjack. Neither is ever passed in.
- `insuranceBet` cannot be negative.

## Saving a round

`RoundDao.saveRound(round, userId)` writes a finished round in one transaction, so either everything lands or nothing does:

1. Insert the game.
2. Insert the hands in order, each split hand after its parent.
3. Insert each hand's cards.
4. Add the round's net result to `chipsOwned`: the sum of `payout - betAmount` over the player's hands, plus `insurancePayout - insuranceBet`.

The bankroll change is derived from the round's own hands, so the two can never disagree. Bets are not debited when placed. The in-flight round lives in the ViewModel until it settles, which is also why states such as "hand still active" are never persisted.

## Statistics

Statistics are derived by DAO queries over the raw history, never stored. `GameHistoryDao` currently provides `observeForUser` and `observeNetChips`. Rules for every future query:

- Filter on `owner = 'PLAYER'` (or `result IS NOT NULL`). Dealer hands have a bet and payout of 0, which looks like a push.
- A win is `payout > betAmount`, a push is `payout = betAmount`, and a loss is `payout < betAmount`. This covers every multiplier tier, including a surrender.
- Statistics about a specific tier (for example, number of 7-7-7s) use `result`. Doubles statistics use `isDoubled`.

## Gradle setup

Version catalog (`gradle/libs.versions.toml`):

```toml
[versions]
ksp = "2.3.11"
room3 = "3.0.3"

[libraries]
androidx-room3-runtime = { group = "androidx.room3", name = "room3-runtime", version.ref = "room3" }
androidx-room3-compiler = { group = "androidx.room3", name = "room3-compiler", version.ref = "room3" }

[plugins]
ksp = { id = "com.google.devtools.ksp", version.ref = "ksp" }
androidx-room3 = { id = "androidx.room3", version.ref = "room3" }
```

Root `build.gradle.kts`:

```kts
plugins {
	alias(libs.plugins.ksp) apply false
	alias(libs.plugins.androidx.room3) apply false
}
```

Module `splithappens/build.gradle.kts`:

```kts
plugins {
	alias(libs.plugins.ksp)
	alias(libs.plugins.androidx.room3)
}

room3 {
	schemaDirectory("$projectDir/schemas")
}

dependencies {
	implementation(libs.androidx.room3.runtime)
	ksp(libs.androidx.room3.compiler)
}
```

Notes:

- KSP is not optional: Room 3 will not build without it. AGP 9 requires KSP 2.3.6 or higher.
- AGP 9 has built-in Kotlin, so there is no `kotlin-android` plugin and no `android.builtInKotlin` flag.
- `schemaDirectory` is required by the Room Gradle plugin. The generated schema JSON files (`schemas/<package>.<DatabaseClass>/<version>.json`) are checked into git; they are used for validation and auto-migrations.
- Stay on Room 3.0.3 or later since 3.0.2 and 3.0.3 fixed a deadlock and an `IllegalMonitorStateException` in `@Transaction` DAO wrappers, which `saveRound` relies on.
- The driver is `AndroidSQLiteDriver` (the platform's SQLite). The alternative is `BundledSQLiteDriver` from `androidx.sqlite:sqlite-bundled`, which ships its own SQLite build at the cost of APK size. Switching later is a one-line change.

## Creating the database

Build the database once and hold the instance in the Application; a `RoomDatabase` is expensive to create.

```kt
fun buildSplitHappensDatabase(context: Context): SplitHappensDatabase =
    Room.databaseBuilder<SplitHappensDatabase>(context.applicationContext, "splithappens.db")
        .setDriver(AndroidSQLiteDriver())
        .build()
```

DAO functions are `suspend` (or return `Flow`), so call them from a coroutine or collect them in the ViewModel.

## Changes from the original ERD

- **Users:** `userId` is a UUID. The profile picture moved to its own `ProfilePictures` table.
- **Sessions:** added `startedAt` and `endedAt`.
- **Games:** added `insuranceBet` and `insurancePayout`. `dealerTotal` is kept as a documented write-once snapshot.
- **Hands:** added `payout` and `isDoubled`. `result` is nullable, and the `HandResult` values carry the payout multipliers.
- **HandCards:** primary key is `(handId, dealtOrder)`.
- **GameHistory:** a derived view instead of a stored table.
